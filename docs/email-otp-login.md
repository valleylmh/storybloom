# 邮箱验证码登录上线配置

前端使用 Supabase `signInWithOtp` 发送、`verifyOtp({ email, token, type: "email" })` 验证；允许新邮箱自动注册。会话继续使用现有持久化和自动刷新配置。旧回调路由保留以接收此前发出的链接。

## 必须先完成的 Supabase 配置

在当前生产项目 Authentication → Email Templates 中，将 Magic Link 模板正文替换为 `supabase/templates/email-otp.html`，标题设置为「StoryBloom 登录验证码」。同时检查 Confirm signup 模板，如该项目新用户注册使用此模板，也替换为同一验证码模板。必须使用 `{{ .Token }}`；只含 `{{ .ConfirmationURL }}` 的模板无法支持新界面。

确认 Email provider 启用、允许新用户注册，SMTP 可以投递给真实用户。验证码长度应在 6–10 位之间（前端允许此范围）；建议有效期 10 分钟。保留服务端发送和验证频率限制。前端 60 秒倒计时只是交互提示，不代替服务端限流。

## 上线验收

1. 已有邮箱收信包含数字验证码，在当前 PWA 输入后登录并回到原页面，无需打开邮件链接。
2. 新邮箱完成相同流程后建立账户。
3. 验证错误、过期和已使用的验证码不能登录；重新发送后使用最新验证码。
4. 连续点击不重复发送；倒计时期间不能重发；更换邮箱后发送到新地址。
5. 关闭重开 PWA 仍保持有效会话；退出登录后受保护页面重新要求登录。

当前只完成代码与模板准备。线上模板修改、真实收信以及新老账户真机验证需要在可访问 Supabase 配置及测试邮箱的环境完成；不能仅以类型检查认定验证码登录已上线。
